01

The hairline test

Each face is drawn to a canvas at its real pixel size, then the thinnest stroke is measured in device pixels. Below about 1px a hairline stops being a line and becomes a grey smear — worse on dark, where antialiasing eats it.

The call · Latin display

Fraunces — with the character axes switched off.

  • It has an optical size axis. Fraunces carries opsz 9–144, which thickens hairlines automatically as the size drops. That is precisely the Bodoni failure mode, solved in the font rather than worked around in CSS.
  • One family covers 88px and 14px. Prata ships a single weight, 400, with no italic. Your system needs display headings, section heads, pull quotes and the occasional 15px label. Prata gives you nothing to recover with when a size gets weak.
  • The trendiness objection is real, and answerable. Fraunces is everywhere right now — but almost always with SOFT and WONK turned up, which is what makes it read as friendly-retro. Set 'SOFT' 0, 'WONK' 0 at weight 200–300 and it is a severe, high-contrast face that very few people are using.
  • Prata stays in the system as an alternate for single large display moments — a report cover, a poster — where nothing sits below 40px. It is the better face at that one job.

Three of those four reasons are facts about the fonts, not measurements — they hold whatever the table says. The table decides one thing: whether either face breaks before 15px. If Prata holds all the way down on your screen, the case for Fraunces rests on range alone, and you should weigh Prata's distinctiveness against it yourself.

02

The Arabic display face

The pairing has to hold as one identity. If the Latin is a high-contrast serif and the Arabic is a low-contrast humanist, they read as two different brands with the same logo on top.

Measured: optical size compensation

Arabic and Latin set at the same font-size do not look the same size — Arabic letterforms sit lower and smaller on the line. Two anchors are measured against Fraunces, both from ink above the baseline only, because Arabic descenders have no Latin counterpart: the body (dotless, ascender-free bowls ص ـهـ) against the x-height, and the alef against the ascender of l. They bracket the multiplier; where inside the bracket it lands is checked by eye at working size, and that value is the token.

The call · Arabic display

Amiri for headings. Reem Kufi for labels.

  • Amiri matches the contrast. It is a Naskh revival with real thick–thin modulation, so it sits beside a high-contrast Latin serif as the same idea rather than a substitute for it.
  • It is genuinely archival. Amiri revives the Bulaq Press types — actual nineteenth-century Egyptian printing. Your brief asks for Al-Khwarizmi as written lineage rather than portraiture; this is that, as a typeface.
  • Reem Kufi earns a second role. It is geometric Kufi — built from circles and straight lines, the same compass-and-rule construction the astrolabe mark uses. Too rigid for running headlines, exactly right for short labels, section markers and tally captions, where Amiri is too delicate.
  • Apply --ar-scale. Amiri needs ×1.15 at every size, or Arabic headings undersell themselves next to the English.
Not taken · El Messiri

A contemporary low-contrast humanist. It is a good typeface and the wrong one here: set next to Fraunces at 200–300 weight it reads as a different, softer brand, and it carries none of the archival quality the rest of the system is built on. If the identity ever moves away from high-contrast serif, revisit it — it would be the right answer then.

03

The scale

Seven steps, no more. Every size is a token; a size that isn't in this list doesn't exist. The base is 16px and the ratio is 1.32, which lands close enough to the existing stroke unit (u = 2) to keep type and geometry on the same grid.

04

The interface face

This is the face that carries almost every word on every surface. It has to be clean enough to disappear, and it has to carry Arabic in the same family — a second family for Arabic is what breaks bilingual systems.

What Hermes actually uses

Inspected directly: their interface runs on Rules Variable at weights 400–500, 13–16px — a commercial Swiss grotesque. Their display face is Rules Gothic Condensed. Their mono, Aeonik Fono, appears only at 10–11px, uppercase, on short labels — never in a sentence, never above 11px. Part of what reads as quality there is simply paid-for type. Rules has no Arabic and isn't licensable for free; the candidates below are the closest free faces that do carry Arabic.

Measured: legibility at small sizes

Two things decide whether a UI face holds at 14px. x-height ratio — the lowercase height against the caps — because it is the lowercase you read; higher is more legible small. Set width — how much room a fixed sentence takes; narrower fits more into a table cell or a chart label without shrinking the type.

The call · interface faces

Readex Pro for Latin. Vazirmatn for Arabic.

  • Readex Pro for the Latin. Low contrast, open apertures, softened terminals — clean without having opinions, which is what lets it sit under a high-contrast serif without fighting it.
  • Vazirmatn for the Arabic, on your judgement. You read Arabic every day; I don't. My case for keeping one family was coherence, and coherence is not worth buying at the cost of the script half your market reads. Splitting is normal in bilingual systems — Latin and Arabic are built so differently that one designer rarely nails both.
  • A split is only safe if it is matched. Two families at the same nominal weight are almost never the same optical weight, and Arabic sets smaller than Latin at the same size. Both are measured below and corrected with per-script tokens rather than by eye.
  • One consequence worth knowing: since Arabic no longer comes from the Latin family, the Arabic-coverage constraint that ruled out Geist, Inter and Manrope no longer binds the Latin slot. You're happy with Readex, so I'd leave it — but the door is open if you ever want to revisit.

Measured: matching the two faces

Two joins have to be made invisible. Optical size — Arabic sets smaller at the same font-size, so it needs a multiplier. Stroke weight — measured on the two simplest verticals in either script, Latin l and Arabic alef ا, which are both a plain stem and therefore directly comparable. If one is thicker, Arabic at 400 will look bolder than Latin at 400 and the page will feel lopsided. Stems are compared at the weight body text actually uses, with the Arabic already scaled by --ar-body-scale — a stem grows with the size it is set at.

The correction · mono budget

The homepage draft broke this rule badly. Every eyebrow, nav link, button, section kicker and caption was mono — which is how a supporting face quietly becomes the brand's voice. Hermes, measured above, never puts mono above 11px and never in a sentence. Three hard limits, so this is checkable rather than a matter of taste:

01
Numerals: mono at any size. Tables, prices, chart values, n = counts. Always tabular. Numbers are the one thing mono exists for.
02
Labels: mono only at ≤11px, uppercase, four words or fewer. Axis labels, source lines, figure numbers, units. One per region of a composition, not one per element.
03
Everything else: never. Nav, buttons, eyebrows above headings, section kickers, form labels, captions, body. All of it is the interface sans. If a run of mono would read as a phrase, it is the wrong face.
The gap nobody notices until launch

IBM Plex Mono has no Arabic. Every chart label, n = line, source credit and timestamp in the Arabic system has no mono to fall back on. The rule: Arabic metadata uses IBM Plex Sans Arabic at weight 400 with font-variant-numeric: tabular-nums and the mono letter-spacing removed — never a Latin mono with Arabic glyphs substituted in, which is what happens by default and looks broken.
